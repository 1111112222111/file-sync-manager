**项目**: 基于 Electron 的桌面端文件自动同步工具，绑定百度网盘实现单向云端备份，支持拖拽上传、文件监听自动同步、云端浏览下载。
**用户角色数**: 1（个人用户）
**P0 功能数**: 6 / P1: 5 / P2: 4

# 需求分析文档: 文件自动同步管理器

## 1. 项目概述

- **一句话描述**: 桌面端文件自动同步工具，将本地文件单向备份至百度网盘，支持拖拽上传、文件变更自动监听同步、云端文件浏览下载，后台静默运行。
- **目标用户**: 个人用户，需要将本地工作文件自动备份到百度网盘，减少手动上传操作。
- **核心价值主张**:
  - 拖拽即上传，零学习成本
  - 文件变更自动检测并同步，无需手动干预
  - 后台托盘运行，不干扰日常工作
  - 统一的云端文件浏览入口，避免频繁打开网盘客户端或网页

## 2. 用户角色

| 角色 | 描述 | 典型场景 | 备注 |
|------|------|---------|------|
| 个人用户 | 有百度网盘账号，需要将本地文件/文件夹自动备份到云端。可能同时管理多个项目的文件。 | 将工作目录注册为监听源，日常编辑文件后自动同步到百度网盘；偶尔需要从云端下载之前备份的文件到本地。 | 唯一角色。首期不涉及团队协作或多用户场景。 |

## 3. 功能列表

| 功能 | 优先级 | 描述 | 依赖 |
|------|--------|------|------|
| 百度网盘 OAuth 授权 | P0 | 用户通过 OAuth 2.0 授权应用访问百度网盘，Token 本地加密存储并支持自动刷新。 | 无 |
| 拖拽上传 | P0 | 用户将文件/文件夹拖拽到应用窗口的指定区域，文件自动加入传输队列上传至百度网盘。 | 百度网盘授权、传输队列 |
| 实时传输进度 | P0 | 上传/下载过程中在 UI 中实时展示文件名、进度百分比、传输速度、剩余时间。 | 传输队列 |
| 云端文件浏览 | P0 | 展示百度网盘指定目录下的文件列表，支持查看文件名、大小、修改时间。 | 百度网盘授权 |
| 云端文件下载 | P0 | 用户从云端文件列表中选择文件，下载到本地指定目录，带进度展示。 | 云端文件浏览、传输队列 |
| 文件监听自动同步 | P0 | 基于 chokidar 监听已注册的文件夹，检测到文件新增/修改/删除后，自动将变更同步至百度网盘。 | 百度网盘授权、传输队列、过滤管理 |
| 传输队列管理 | P1 | 所有上传/下载任务进入统一队列，支持并发控制（默认 3 个）、暂停/恢复/取消单个任务，失败自动重试（最多 3 次，指数退避）。 | 无 |
| 冲突检测与处理 | P1 | 上传前检查云端文件修改时间，若云端版本比本地新则弹窗询问用户：保留本地版本、保留云端版本、保留两份（云端重命名 + 上传本地版）。 | 百度网盘授权 |
| 文件过滤规则 | P1 | 用户可在设置中配置排除规则（文件/文件夹名，支持通配符），被排除的文件不会被监听同步。默认无排除规则（全量同步）。 | 文件监听 |
| 系统托盘 | P1 | 应用关闭窗口时最小化至系统托盘而非退出。托盘图标显示同步状态，右键菜单提供：打开主窗口、暂停/恢复同步、查看最近传输、打开设置、退出。 | 无 |
| 深色/浅色主题切换 | P1 | 应用支持深色和浅色两种视觉主题，用户可在设置中切换，默认跟随系统主题。 | 无 |
| 开机自启 | P2 | 用户可在设置中开启/关闭开机自动启动，基于 electron-auto-launch 实现。 | 无 |
| 桌面通知 | P2 | 上传完成、下载完成、冲突发生、传输错误时，通过系统通知提醒用户。 | 系统托盘 |
| 传输历史记录 | P2 | 持久化存储传输任务记录（文件名、方向、状态、时间），用户可在历史面板中查看最近的传输活动。 | 传输队列 |
| 多监听源管理 | P2 | 除默认工作区外，用户可注册任意本地文件夹为监听源，每个监听源独立配置过滤规则，统一同步到百度网盘。 | 文件监听、过滤管理 |

## 4. 核心用户流程

### 流程一: 首次使用并上传文件

```
1. 用户启动应用 → 看到欢迎页，提示授权百度网盘
2. 用户点击"授权百度网盘" → 弹出 OAuth 授权窗口 → 用户登录百度账号并授权
3. 授权成功 → 应用展示主界面，包含拖拽上传区域
4. 用户从文件管理器拖拽一个文件到拖拽区域
5. 文件立即加入传输队列 → 进度条显示上传进度
6. 上传完成 → 桌面通知"上传成功"，文件出现在传输历史中
```

### 流程二: 注册文件夹并自动同步

```
1. 用户在设置页点击"添加监听文件夹" → 选择本地文件夹
2. 文件夹被注册到监听器 → chokidar 开始监听该目录
3. 用户在监听文件夹中修改了一个 .docx 文件并保存
4. chokidar 检测到 change 事件 → 过滤管理器检查（未被排除）→ 防抖 300ms
5. 文件加入传输队列 → 冲突检测（云端无更新，跳过冲突）→ 自动上传
6. 上传完成 → 托盘图标恢复常态 → 传输历史记录更新
```

### 流程三: 浏览云端文件并下载

```
1. 用户点击导航栏"云端文件"
2. 应用调用百度网盘 API 获取文件列表 → UI 展示网格/列表视图
3. 用户找到目标文件，点击"下载"
4. 下载任务加入传输队列 → 进度显示
5. 下载完成 → 文件保存到本地工作区 → 桌面通知"下载完成"
```

### 流程四: 冲突处理

```
1. 用户在本地修改了 report.xlsx 并保存 → 自动触发上传
2. 冲突检测器发现云端 report.xlsx 的修改时间比本地版本更新（可能在其他设备上修改过）
3. UI 弹出冲突对话框，展示三个选项：
   a. 保留本地版本（上传覆盖云端）
   b. 保留云端版本（跳过本次上传）
   c. 保留两份（云端重命名为 report_conflict_2026-05-26.xlsx，然后上传本地版本）
4. 用户选择后 → 按选择执行操作 → 记录处理结果
```

## 5. 方案对比

| 方案 | 优点 | 缺点 | 推荐？ |
|------|------|------|--------|
| A: Electron + React + TypeScript | 跨平台支持（Win/Mac/Linux）；Node.js 生态直接访问文件系统；chokidar/electron-store 等成熟库开箱即用；社区庞大，问题容易解决。 | 打包体积较大（约 150MB+）；内存占用相对较高。 | 推荐 |
| B: Tauri + React + Rust | 打包体积小（约 10MB）；内存占用低；安全性更好。 | Rust 学习曲线陡峭；文件监听和系统托盘需要更多自定义实现；网盘 SDK 集成需自行封装 HTTP 客户端，社区资源较少。 | 不推荐（首期追求开发效率） |
| C: 纯 Web 应用（浏览器 + PWA） | 零安装；跨平台天然支持。 | 无法访问本地文件系统进行监听；无法最小化到系统托盘；无法开机自启；依赖浏览器运行，体验不如原生应用。 | 不推荐（无法满足核心需求） |

**推荐方案 A**，理由：

1. **chokidar 文件监听**是 Electron/Node.js 生态中最成熟的能力，Tauri 的 Rust 端虽然也有文件监听库（notify），但成熟度和社区支持不如 chokidar。
2. **系统托盘**、**开机自启**等桌面特性在 Electron 中有成熟的 API 和第三方库支持。
3. 技术栈（TypeScript + React）在前端和 Node 侧统一语言，降低开发心智负担。
4. 架构预留的**适配器接口**允许后续扩展其他云盘，Electron 的 HTTP 客户端生态对此友好。

## 6. 非功能需求

### 性能
- 上传/下载操作在主进程异步执行，不阻塞 UI 渲染
- 传输进度更新频率：每 100ms 推送一次（防抖），避免 UI 频繁刷新
- 文件监听防抖延迟：300ms，合并短时间内同一文件的多次变更事件
- 最大并发传输数：3（可配置），避免过多并发导致网盘 API 限流
- 大文件（>100MB）传输应保持 UI 响应，进度更新不卡顿

### 安全
- 百度网盘 OAuth Token 使用 electron-store 加密存储，不外泄
- 不在日志中记录 Token 或敏感路径信息
- OAuth 授权回调使用本地 HTTP 服务器（localhost），不暴露到公网
- 传输过程使用 HTTPS

### 兼容性
- 操作系统：Windows 10+、macOS 11+、Linux (Ubuntu 20.04+)
- 百度网盘 API：使用官方 Open API 最新稳定版本
- 支持中文文件名、长路径（Windows 260 字符限制需特别处理）

### 可靠性
- 网络中断后自动重试传输任务，最多 3 次，指数退避（1s / 2s / 4s）
- 应用崩溃后，未完成的传输任务在下次启动时从持久化队列恢复
- 队列持久化存储（SQLite），确保任务不丢失
- Token 过期自动刷新，无需用户重新授权

### 可用性
- 拖拽区域在未授权状态下显示醒目的引导提示
- 传输进度在任务栏缩略图（Windows）和托盘图标上可视化展示
- 所有可逆操作（删除、取消任务）需二次确认
- 第一次使用时提供快速引导流程

## 7. 异常处理

| 异常场景 | 处理方式 |
|---------|---------|
| 百度网盘 OAuth 授权失败（用户拒绝或网络错误） | 展示错误提示，提供"重新授权"按钮。应用降级为仅本地模式，云端功能不可用。 |
| 百度网盘 Token 过期 | 自动使用 refresh token 刷新。若刷新失败，通知用户并引导重新授权。 |
| 上传过程中网络中断 | 任务标记为"失败"，自动重试（最多 3 次指数退避）。超过重试次数后标记为"永久失败"，通知用户。 |
| 上传的文件正在被其他程序占用（如 Office 打开中） | 检测文件锁定状态，若无法读取则跳过并通知用户"文件 xxx 正被占用，无法同步"。下次文件解锁后 chokidar 会再次触发 change 事件自动重试。 |
| 百度网盘存储空间不足 | 上传前检查配额，若空间不足则拒绝上传并弹窗提示用户清理云端空间。 |
| 百度网盘 API 限流（QPS 超限） | 传输队列内置请求间隔控制，遇到 429 响应时自动等待并重试。 |
| 本地磁盘空间不足（下载时） | 下载前检查目标磁盘剩余空间，不足时拒绝下载并提示用户。 |
| 监听文件夹被删除或移动 | chokidar 检测到目录不可访问，通知用户"监听源 xxx 已不可用"，在设置页将该监听源标记为异常状态。 |
| 云端文件在下载过程中被删除 | 下载失败，通知用户"远端文件已不存在"。 |
| 文件名包含特殊字符导致云端存储失败 | 文件名转义处理（百度网盘 API 允许的字符范围），非法字符自动替换为下划线并通知用户。 |
| 应用退出时仍有传输任务进行中 | 弹窗询问用户"还有 N 个任务进行中，确定退出？"，确认后持久化未完成任务，下次启动恢复。 |

## 8. 已确认决策（原开放问题）

1. **拖拽上传行为**：拖拽仅作为上传交互，文件保留在原路径，不复制到额外的工作区目录。拖拽 = 选择文件并触发上传。
2. **百度网盘远程目录映射**：统一上传到网盘指定的远程根目录（如 `/我的同步文件/`），用户可在设置中配置该根目录路径。
3. **文件删除同步行为**：默认不同步删除（纯备份模式），本地文件删除后云端保留。后续可作为可配置选项。
4. **托盘通知策略**：提供"全部通知 / 仅错误和冲突 / 关闭通知"三档，用户可在设置中选择。
5. **安装包体积**：用户已了解 Electron 打包体积（~150MB），可以接受。
6. **macOS 签名**：首期暂不考虑，优先 Windows 平台。

## 9. 备注

### 竞品参考
- **百度网盘官方客户端**: 功能全面但无文件监听自动同步能力，无第三方网盘扩展接口。
- **GoodSync / SyncBack**: 专业的文件同步工具，支持多目标（本地、FTP、云存储），但不直接支持百度网盘 API。
- **Rclone**: 命令行云存储同步工具，功能强大但无 GUI，不适合普通用户。其适配器架构值得参考。

### 头脑风暴补充
- 首期聚焦**单向备份（本地到云端）**，下载为手动操作。这简化了同步逻辑，避免了双向同步的复杂性（双向冲突、删除传播等）。
- 架构预留的 **ICloudAdapter 适配器接口**是一项前瞻性设计，确保后续接入阿里云盘、OneDrive 等时，核心同步引擎无需大量改动。
- **简单覆盖**的版本策略意味着不保留云端文件历史版本，这与用户"网盘做备份"的场景一致。若后续需要版本历史，可依赖百度网盘自身的文件历史功能。

### 风险提示
1. **百度网盘 API 依赖风险**: 百度网盘 Open API 的可用性、限流策略、接口变更不在控制范围内，需关注 API 变更公告。建议关键接口（上传/下载/列表）做兼容性适配。
2. **大文件传输体验**: 单文件超过 1GB 时，百度网盘 API 的上传速度和稳定性需要实测验证，必要时引入分片上传。
3. **chokidar 跨平台差异**: Windows/macOS/Linux 的文件系统事件机制不同（如 macOS 的 fsevents、Windows 的 ReadDirectoryChangesW），chokidar 已做封装但极端情况下可能有差异，需要在各平台实测。
4. **开机自启兼容性**: Windows 上通过注册表实现、macOS 通过 LaunchAgent、Linux 通过 autostart .desktop 文件，不同平台的实现细节和权限需求不同，需逐一验证。
